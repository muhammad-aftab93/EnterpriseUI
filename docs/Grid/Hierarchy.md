## Overview

Expand a customer to see its orders, and an order to see its lines. Relations nest without a depth limit; children can load lazily on first expansion.

- Nested relations
- Lazy loading
- Expand/collapse all
- Child columns
- Search reveals matches

## Architecture notes

Expanded relations contribute DetailHeader and DetailData rows to the materialized row list, so selection, search and export all see them.

## Best practices

Provide ChildColumns for important child tables, use lazy loading for remote children, and keep nesting depth reasonable for readability.

## Performance notes

Children are indexed once per relation (a dictionary lookup per parent). Lazy relations load on first expansion and cache the result until the grid refreshes.

Measured numbers are in [PerformanceReport](Reports/PerformanceReport.md).

## Accessibility notes

Detail rows announce their level and expanded state; Alt+Right and Alt+Left expand and collapse the focused row.

## Troubleshooting

A relation that shows no children usually has mismatched key types (int versus long) or the wrong field names; set ChildItemType so columns can be generated for empty tables.

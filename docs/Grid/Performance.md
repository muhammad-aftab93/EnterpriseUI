## Overview

Bind, sort, filter and group one million in-memory rows and see the elapsed time of each operation measured on this machine.

- 1M rows
- Windowed rows
- Timed sort/filter/group
- Materialized groups

## Architecture notes

Rendering and data are decoupled: the engine returns windows, the control paints the visible rows. Queries run in the data layer (expression trees over IQueryable, cached per source).

## Best practices

Bind lists directly, avoid per-row work in events, keep row height fixed, and measure with the benchmark project before tuning.

## Performance notes

Results depend on hardware and data shape. Run the BenchmarkDotNet-style harness in benchmarks/EnterpriseUI.Benchmarks for repeatable numbers (memory, render, scroll, filter and grouping).

Measured numbers are in [PerformanceReport](Reports/PerformanceReport.md).

## Accessibility notes

Large grids stay keyboard operable because focus moves by display index and scrolls the focus cell into view without materializing other rows.

## Troubleshooting

If grouping a million rows feels slow, group by a low-cardinality column and collapse groups by default.

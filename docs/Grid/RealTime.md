## Overview

Quotes implement INotifyPropertyChanged and tick many times a second. The grid repaints changed rows, keeps selection and re-sorts when a sorted column changes.

- INotifyPropertyChanged tracking
- Live re-sort
- Conditional colors
- Update rate control

## Architecture notes

Items that implement INotifyPropertyChanged are observed while they are in the rendered window. Changes repaint or, when they can affect sorting, grouping, filtering or summaries, trigger a debounced re-query.

## Usage guide

Make the row type raise PropertyChanged and bind it; set ObserveItemChanges = false to pause, and call Engine.NotifyDataChanged() after bulk external changes.

## Best practices

Raise PropertyChanged on the UI thread or marshal first, batch bulk updates, and avoid sorting on a field that changes many times per second.

## Performance notes

Observers are limited to the rendered window (at most 2,000 items), so streaming into a million-row source does not subscribe a million handlers.

Measured numbers are in [PerformanceReport](Reports/PerformanceReport.md).

## Accessibility notes

Rapid updates do not spam screen readers: value changes are not announced individually, only query-level events (sort, filter, page) are.

## Troubleshooting

If values change but the grid does not repaint, the item type does not raise PropertyChanged (or ObserveItemChanges is false). For bulk external changes call NotifyDataChanged.

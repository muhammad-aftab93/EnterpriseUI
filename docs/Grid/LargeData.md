## Overview

Reads a 500,000-row store through an asynchronous data source with simulated latency. Sorting, filtering and paging run in the data source; failures show an error state you can retry.

- IDataSource<T>
- Server paging
- Latency handling
- Cancellation of stale requests
- Error state and retry
- Infinite scroll

## Architecture notes

Remote requests are described by DataSourceRequest and can be translated to OData with ODataQueryBuilder.

## Usage guide

grid.CustomDataSource = new RemoteDataSource<T>(async (request, ct) => await api.QueryAsync(request, ct)); grid.PagingMode = GridPagingMode.Server;

## Best practices

Implement paging, sorting and filtering in the source, keep requests cancellable, and show errors with a retry.

## Performance notes

Only the requested page is transferred. The grid asks for the visible window plus a small buffer and caches the last window.

Measured numbers are in [PerformanceReport](Reports/PerformanceReport.md).

## Accessibility notes

Loading and error states are real text ('Loading...', 'Data could not be loaded: ...') that screen readers can read, not only spinners or colors.

## Troubleshooting

If rows never appear, check LastError; a source that throws puts the grid in an error state until RefreshDataAsync succeeds.
